# 流程

## F1 看板推进度（主路径）

1. 入口：一级导航不含看板（侧栏 3 项：收件箱 / 产品 / 执行节点；移动 TabBar 3 项：收件箱 / 产品 / 更多）；`#/` 仍直达上次访问的项目看板（localStorage），无记录则产品页；看板入口 = 产品 → 项目列表 → 打开看板。`/projects/*` 下钻高亮父域「产品」。
2. 步骤：看板 7 列 → 点任务卡 → 详情路由 `#/projects/:pid/tasks/:tid`（桌面右侧 720px 抽屉，移动全屏 sheet）→ 读附件 → 提交评审。
3. 分支：面包屑按名显示「产品 / <产品名> / <项目名>」，中间产品段可点回 `#/products/:productId/projects`，当前项目段是末段不可点（带 `:taskId` 时项目段变链接）；名字由壳层反查（`GET /v1/projects?id=` + `GET /v1/products?id=`，会话内按 id 缓存）——取不到名字时退回 ID（项目失败 → `产品 / <project_id>`，产品失败 → `产品 / <productId>`），静默降级、不弹错误条、不阻塞渲染。无 `taskId`（旧收藏/历史）→ 回看板；列表 404/超时 → 错误条 + 保留上次数据；`in_review` 才有评审区；`failed` 才有重置入口。
4. 退出：提交结论后关闭抽屉、回到原看板并触发一次 `refresh('write')`；关闭抽屉 = URL 回看板路由。
5. 状态留存：列折叠偏好存 localStorage；筛选（kind/status）进 URL query；滚动位置不保留（详情是独立路由）。

## F2 读附件 markdown（应用内）

1. 入口：详情「附件」区，`input`/`output` 任一。
2. 步骤：点附件 → 加载正文 → 渲染（marked + DOMPurify）→ ≥1024 整页居中的 80% 浮层（底图为看板 / 项目列表整页，详情抽屉在预览期间隐去，画面里没有侧边抽屉）、<1024 详情内二级面板（768–1023 抽屉 720 / <768 全屏堆叠）。
3. 分支：404 → 错误条 + 「在新标签打开原文」；413 → 「附件过大」；超时 → 「加载超时，重试」；`Content-Length > 512 KB` → 提示 + 「仍然加载」；正文为空 → 空态；渲染异常 → 降级 `<pre>` 原文；正文内嵌图片 → 显式占位（不静默空白）。
4. 退出：Esc / 关闭键只退浮层，回详情并保留滚动位置（二级层，不动详情状态），焦点回触发的附件行。
5. 状态留存：浏览器 HTTP 缓存（`Cache-Control: immutable` + ETag）直接复用，前端不自建缓存，只做同 `material_id` 并发去重。

## F3 评审（写操作，带门禁）

1. 入口：`in_review` 任务详情「评审」区；收件箱「待审核」区也可进入同一详情。
2. 步骤：选「通过 / 驳回」→ 被评审附件自动带入 `output` 项（不手输 material_id）→ 驳回必填意见 → 提交。
3. 分支：服务端非 2xx（任务已被他人处理）→ 错误条显示服务端 message + 立即重拉详情；重复提交 → 按钮 loading 后禁用。
4. 退出：成功后关闭抽屉回看板，状态列随之变化。
5. 状态留存：评审意见不持久化草稿（刷新即丢），避免误提交旧文本。

## F4 移动端三条（验收口径见 screens 状态矩阵）

1. 横向切列：看板列宽 `min(86vw,320px)`，`scroll-snap: x mandatory`，列头 sticky，顶部「第 N / 7 列」指示器；滚到底最后一列完整可见。
2. 读附件：详情为全屏 sheet，附件正文在应用内渲染，不新开标签。
3. 推进状态：`in_review` 时底部固定操作条（取消 / 驳回 / 通过并关闭），二次确认，触控 ≥44×44，操作条与滚动区分离防误触。

## F5 关闭/重开项目（写操作，带二次确认）

1. 入口：项目列表 `#/products/:productId/projects` 行内「关闭/重开」（`ghost`；open → 「关闭」、closed → 「重开」）。行内按钮阻断冒泡，不打开行详情抽屉。
2. 步骤：「关闭」→ `POST /v1/projects/close?id=`；成功后该行状态变「已关闭」、按钮变「重开」，页头项目数与筛选结果随之刷新。「重开」→ `POST /v1/projects/reopen?id=`；成功后该行回 open。
3. 分支：关闭返回 **409**（项目下仍有未完成任务）→ `ui/ConfirmModal` 二次确认，标题「关闭项目需要确认」，说明「还有 N 个未完成任务，确认关闭会取消它们，且重开不会恢复」；取消 = 不发请求，确认 = 以 `force=true` 重发。其它非 2xx → 错误条「关闭项目失败 / 重开项目失败」（detail 为服务端原文）+「重试」。重开**不复活**已取消的任务（后端口径：只回项目状态）。
4. 退出：动作完成停在项目列表（不跳转、不弹 toast，行状态变化即反馈）；若该行的详情抽屉开着，抽屉内状态与关闭时间字段同步更新。
5. 状态留存：closed 项目的「打开看板」仍可用（只读）；看板页头显示「已关闭标识」且「新建任务」`disabled`；`#/` 与上次项目记忆不受关闭/重开影响。
