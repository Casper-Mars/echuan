# v2 死代码清单（deadcode 扫描，2026-11-23）

## 结论

`main` 只装 v3 服务，但 v2 编排层仍留在仓库里。`deadcode` 从 `./cmd/echuan` 扫出 **412 个不可达函数**，分布在 **61 个文件**（43 个文件全部函数不可达，18 个文件部分不可达）。

**不能一把 `git rm` 掉**：已实测，43 个"全死"文件里混着活代码仍在用的共享类型（`domain.Project` / `domain.Material` / IM 的 `CardStore` / `Messenger` / `DocProvider` / `CardRecord`）。直接删会编译失败，说明这些文件的死是"函数层死、类型层活"，需要先把类型拆出来再删函数。

## 扫描方法

```bash
GOPROXY=https://goproxy.cn,direct GOSUMDB=off \
  go run golang.org/x/tools/cmd/deadcode@latest ./cmd/echuan
```

（`sum.golang.org` 在本地不可达，必须换 goproxy + `GOSUMDB=off`。）

## 建议拆成三片做（每片以 `go build ./... && go test ./...` 为门禁）

1. **API 层**：`internal/api/{projects,work_items,specs,spec_documents,plans,package,inbox,gate_decisions,workers}.go` + `router.go`。前提：把 v3 复用到的响应 DTO / 错误辅助拆到独立文件。
2. **app 层**：`internal/app/{project,work_item,worker,phase,claim,inbox,decide,spec*,package,plan,breakdown,gate_decision,im_bridge,reclaimer}.go`。前提：`domain.Project` / `domain.Material` 等类型移到 `domain/` 下独立文件。
3. **store + IM 层**：`store/{work_item*,worker,project,spec,gate_decision,inbox,im_doc}.go`、`im/{poller,docs,feishu/importer}.go`。前提：`CardStore` / `Messenger` / `DocProvider` / `CardRecord` 接口拆到 `im/contract.go`。

每片预计删 8–15 个文件、连带删除对应 v2 测试（`*_test.go` 里测 v2 行为的部分）。不建议一次做完，单片可独立回滚。
