# 项目详情「资料」区（v0.1）

- 级别：`s`（单屏、单区块，不改数据模型）
- 状态：待评审
- 前置：`GET /v1/projects/materials`（echuan `623d660` 已上线）

## 1 结论

在项目只读详情抽屉里新增「资料」区块，数据取 `GET /v1/projects/materials?id=`，按材料类型分组展示；**简报不单独成条**，作为其对应正文版本的附属行展示（靠 `source_material_id` 配对）。

## 2 目标 / 非目标

**目标**

- 打开项目即可看到该项目所有产物（需求 / 方案 / 拆分 / 报告），不需要逐个任务点进去。
- 简报与其正文版本一眼可辨：版本下面挂一条「简报」。
- 点击可读正文，不跳页。

**非目标**

- 不改数据模型、不加新接口（现有派生接口已够）。
- 不在项目层做编辑、删除、上传。
- 不做跨项目搜索、不做全文检索。
- 不在任务详情重复同一区块（本期只做项目详情）。

## 3 现状

- `ProjectDetailSheet` 当前是**纯派生、0 请求**：9 个字段全部来自列表行（`design/screens/projects.md`「交互」明文写「抽屉不发请求」）。
- 附件展示只在任务详情（`features/task-detail/attachment-preview.tsx` + `ui/AttachmentRow`）。
- 因此本期必须改契约：抽屉从「0 请求」变为「打开时拉一次资料，按需拉正文」。

## 4 方案

### 4.1 位置与结构

抽屉原有 9 个键值字段之后，追加一个「资料」区块：

```
资料（16）
├─ 需求 (2)
│   需求 v2 · 输出                        [展开]
│     └ 简报                              [展开]
│   需求 v1 · 输出                        [展开]
│     └ 简报
├─ 方案 (1)
│   技术方案 · 输出                       [展开]
├─ 拆分 (1)
│   10 卡计划 · 输出                      [展开]
└─ 报告 (12)                [展开全部 / 收起]
```

- 分组顺序固定：需求 → 方案 → 拆分 → 报告 → 其他。
- 组内按附件插入顺序**倒序**（接口按 id 升序返回，前端反转即可，不需要新字段）。
- 报告类默认只显示 5 条，超出给「展开全部」。
- 组内为空则不渲染该组；全部为空显示「暂无资料」。

### 4.2 简报的展示规则

- 判定：`item.kind === 'context' && item.source_material_id` 的材料视为「简报」。
- 只渲染在 `source_material_id` 对应的那条正文下面，缩进一级 + 「简报」徽标。
- 孤儿简报（`source_material_id` 不在本次列表里）归入「其他」组，标题前加「[简报]」，不丢数据。

### 4.3 交互

- 点击任意材料行：在**行下方内联展开**正文（`ui/MarkdownViewer`），再点收起。
- 正文按需拉取：`GET /v1/materials?id=<material_id>`，同一材料只拉一次，结果缓存在组件内（抽屉关闭即丢）。
- 拉取失败：行下方显示错误条 + 「重试」，不阻塞其他行。
- 键盘：行是按钮，Enter/Space 展开；焦点不丢。

### 4.4 状态

| 状态 | 呈现 |
|---|---|
| 加载中 | 3 条骨架行（复用 `SkeletonCard` 的行高口径） |
| 空 | 区块内「暂无资料」空态，不整屏空态 |
| 失败 | 区块内错误条 + 「重试」，不关闭抽屉 |
| 长列表 | 报告组折叠阈值 5 条 |

## 5 契约改动（必须同批）

`design/screens/projects.md`：

- 「交互」段把「抽屉不发请求」改为「抽屉打开时拉取项目资料；字段仍取当前行，资料按需拉取」。
- 新增「资料区」小节：位置、分组顺序、倒序、简报配对、折叠阈值。

`design/components.md`：

- `AttachmentRow` 增加「缩进变体（`indent`）」或新增私有行组件 `MaterialRow`（二选一，倾向后者：项目资料行有「简报」徽标与分组语义，塞进 `ui/AttachmentRow` 会让导出面职责膨胀）。
- 若新增 `MaterialRow`，它落在 `features/projects/`，**不进** `ui/` 导出面（仍是 21 个组件）。

## 6 接口

```http
GET /v1/projects/materials?id=<project_id>
→ 200 { items: [ { material_id, title, kind, role, source_material_id? } ] }
```

- `kind`：requirement / design / plan / report / context / other。
- 已知限制：返回项不含时间与大小 → **首版不显示时间**；若后续要时间，给该接口加 `create_time` 即可，属接口小改（登记为 U-01）。

## 8 验收

- AC1：打开任一项目，抽屉在 1 秒内显示「资料」区；接口失败时显示错误条与重试，抽屉不关。
- AC2：`echuan-1` 这类项目显示 16 条，分组为 拆分 1 / 报告 15，与接口返回一致。
- AC3：构造一份「正文 v1 + 简报 v1 + 正文 v2 + 简报 v2」的项目，简报分别缩进挂在对应正文下，不单独成条。
- AC4：孤儿简报（source 不存在）落在「其他」组，不丢失。
- AC5：点击行展开正文、再点收起；同一材料只发一次下载请求。
- AC6：报告组超过 5 条时折叠，可展开/收起。
- AC7：`make web` 门禁通过（style-debt / size / build），无新增单类名覆盖 Mantine 的写法。
- AC8：键盘 Tab 可达每行，Enter 展开；焦点不丢。

## 9 风险与回滚

- **风险**：抽屉从 0 请求变为有请求，慢网下会出现「抽屉已开、资料区还在转」的中间态 → 用区块内骨架，不阻塞字段显示。
- **风险**：项目任务多时材料列表很长 → 报告组折叠；接口按项目 id 一次返回，不做分页（单项目量级可控，实测 16 条）。
- **回滚**：纯前端特性 + 契约文案；`git revert` 单卡提交即可，无数据迁移、无接口变更。
