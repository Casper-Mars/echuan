# 驿传工作项协议

本文只描述驿传平台的工作项规则：字段含义、状态流转、租约归属、报告契约、门禁红线。
「谁来做、怎么做、什么时候派发」不属于本文——由各领域角色自己的规范决定。

## 1. 工作项是什么

- 工作项来自 `/v1/tasks/claim` 领卡，或 Worker 心跳投递到会话的派单消息；两者字段相同。
- `task_id` / `lease_id` / `project_id` / `material_id` 只能来自派单消息或平台回包，禁止编造。
- `kind` 决定交付物形态：

| kind | 交付物 | 说明 |
| --- | --- | --- |
| `requirement` | 需求正文（Markdown） | 平台落成需求资料 |
| `design` | 技术方案正文（Markdown） | 平台落成方案资料 |
| `breakdown` | `{"items":[...]}` 计划 JSON | 平台按计划生成 N 条 dev 任务 |
| `dev` | 代码交付 + 报告 | 实现与验证方式由领域规范定义 |

- 阶段卡（`requirement` / `design` / `breakdown`）不产生代码交付物。
- 一张卡对应一次交付：交付后等平台结论，不重复用旧 `lease_id` 提交。

## 2. 字段与状态

状态只由平台产生：`pending` → `in_progress` → `in_review` → `done` / `cancelled`。
Agent 不改状态、不改优先级、不取消任务。

- `status` / `attempt` / `max_attempts`：尝试次数接近上限时不要整卡重写。
- `rework=true` 或 `reason` 非空：上一版被驳回，本次只改该原因。
- `description_md` / `context_md`：任务正文与上下文；需要项目或物料全文时用只读工具取，不靠标题猜。
- `inputs` / `upstream`：上游产物只给 `material_id`，正文按需 `echuan_material_get`。

## 3. 租约

- 租约由**领卡方**持有：`lease_id` + `lease_until`（TTL，秒）。
- Worker 心跳派发的卡：租约由心跳托管，**不要**调续租工具，否则会和心跳抢租约语义，把卡搞成 `lease_lost`。
- 手动 `echuan_task_claim` 领的卡：租约自己负责，剩余时间不够收尾时先 `echuan_task_renew`，之后一律用新 `lease_id`。
- 续租返回 `lease_lost`：之前的结果不能再提交，重新领卡，不要拿旧 `lease_id` 硬提交。
- 租约属于领卡方，不随会话内部分工转移：谁领的卡，谁负责最终 `echuan_task_report`。

## 4. 报告契约

任何交付都必须调 `echuan_task_report`；只在会话里说「做完了」平台看不到。

- `dev` 卡：`echuan_task_report(task_id, lease_id, summary_md=...)`，平台落成 report 资料并转 `in_review`。
- 阶段卡：同样的调用，`summary_md` 就是需求 / 方案 / 计划正文。
- `breakdown` 的 `summary_md` 是 JSON 文档：

  ```json
  {"items":[{"seq_no":1,"title":"...","body_md":"...","priority":0,"depends_on":[1]}]}
  ```

  有先后顺序必须写 `depends_on`；不写按并行派发，下游不会等上游。
- 报告正文固定四段，缺一段视为未完成：
  1. **改了什么**：改动的文件或模块与行为变化，一条一句，不写「优化了一下」。
  2. **怎么自检**：实际执行过的命令与结果，贴关键输出行；没跑过的不写。
  3. **git 交付**：分支名、commit、推送校验结果、PR 或 compare 链接。代码交付的分支与 PR 规则由领域规范定义。
  4. **遗留风险**：未覆盖边界、未验证假设；没有就写「无」。
- 被 400 / 409 拒绝时卡仍在你手里：按 `details` 的 `field` / `reason` 修正后，用**同一个 `lease_id`** 重报，不要重新领卡。
- 提交成功后不要用旧 `lease_id` 重复提交同一张卡。

## 5. 卡住也要报告

用 `echuan_task_report` 写清三件事：

- **卡在哪**：具体的报错、失败的命令、缺失的前置条件（附原始输出）。
- **缺什么**：权限、数据、依赖、环境，还是需要人拍板。
- **需要谁决策**：指向具体角色，不写「等通知」。

禁止静默失败，禁止把没做完的写成「已完成」，禁止伪造自检结果。

## 6. 门禁红线

- 不验收：验收结论由平台侧人工给出；agent 只陈述事实，不写「已通过验收」。
- 不返工判定、不取消任务、不改任务状态与优先级、不自造状态流转。
- 不调用任何门禁类接口。

## 7. 空结果与错误

- `echuan_task_claim` 返回「当前无活」（HTTP 204）是正常结果：不连刷、不造任务，等下一轮。
- 字段校验失败（400 / 409）按 `details` 修正后重报；租约类错误按 §3 处理。
- 读类工具返回空集是正常结果，不代表任务失败。

## 8. 一页速查

| 场景 | 动作 |
| --- | --- |
| 拿到工作项 | 字段来自派单或回包，不编造；`kind` 决定交付物 |
| 阶段卡 | `summary_md` 直接写正文；`breakdown` 是计划 JSON |
| 返工卡 | 只改被指出的原因，逐条回应 |
| 租约 | 心跳托管的卡不碰续租；手动领的卡到期前自己续 |
| 交付 | `echuan_task_report` + 四段式；成功后不重复提交 |
| 卡住 | 用同一工具报告卡点，不静默失败 |
| 验收 / 状态 | 一律不碰 |
| 无活 204 | 等下一轮 |
